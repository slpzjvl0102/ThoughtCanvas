ThoughtCanvas — Windows Prototype 0.6.2
2026-11-10 · PC / 노트북

시작
1. ZIP 전체를 새 폴더에 압축 해제하고 ThoughtCanvas.exe를 실행합니다.
2. PC와 노트북 모두 같은 0.6.6 버전을 사용하세요.
3. 작업 → 연결 설정에서 기기 이름과 각 기기의 Google Drive 폴더 경로를 설정합니다.
4. 기존 Local 데이터(%LOCALAPPDATA%\ThoughtCanvas)는 유지됩니다. 이전 실행파일은 닫고 새 버전을 실행하세요.

입력
Pen 필기 / S Pen Button: Pen → Eraser → Lasso 순환.
NT950QDA S Pen의 Invert/Eraser 신호 처리 포함. v0.5.5에서 사용자 실기기 동작 확인.
한 손가락 이동 / 두 손가락 이동·확대·축소 / 회전 없음.
Mouse 좌클릭 현재 Tool / 우클릭 이동 / Wheel 확대·축소.
Wheel Click 유지 후 Drag: 위 Pen, 오른쪽 Eraser, 아래 Lasso, 왼쪽 Text.
Eraser는 접촉 부분만 삭제. Lasso는 완전히 포함된 요소 선택. Shift+Click 추가·해제.
선택 이동·크기 변경 / Undo·Redo 50회 / Text 재편집 / 기본 맑은 고딕.
Dark mode, 크기 원·숫자, 감지 해제 시 마지막 위치 유지, F11 UI 숨기기.

기기 간 작업
시작 및 15초 간격으로 Drive 저장본 목록을 확인합니다. ↻로 수동 갱신할 수 있습니다.
☁ 항목을 선택하면 원래 Board ID로 이어 엽니다.
Local과 다른 기기의 내용이 다르면 Canvas를 열기 전에 선택합니다:
- 이 기기 유지: 다른 기기 원본도 별도 보관
- 다른 기기 사용: 현재 원본도 별도 보관
- 빈 공간에 합치기: 동일 요소를 제외한 변경 내용을 오른쪽 빈 공간에 삽입
합칠 때 삭제를 임의 추정하지 않으며, 유사·중복 내용은 검증 목록에서 확인합니다.
문서 차이는 갱신 제안으로 보존합니다. 통합 전 양쪽 원본과 과거 출처를 보관합니다.
작업 → 다른 기기 변경 확인에서 현재 Board의 변경을 비교합니다.
작업 → 등록 기기에서 기기 이름을 확인합니다. 이름 수정은 연결 설정에서 합니다.
Offline 중 작업은 Local에 저장하고, 감지된 미전송 작업은 연결 복구 후 시작 화면에서 확인합니다.
Network 판별은 Windows 연결 상태와 Drive 폴더 접근 기준입니다. Cloud 업로드 완료 여부는 Google Drive 앱에서 확인해야 합니다.
이전 버전에서 이미 만든 ‘Drive 복사본’은 별도 Board로 유지됩니다. 앞으로 같은 Board를 이어 쓰려면 ☁ 원본을 여세요.

PC·노트북 공동 편집
같은 Network에서 작업 → PC·노트북 공동 편집 → 현재 Board 공유 시작.
다른 기기에서 Code로 참여를 선택하고 표시된 Code를 입력합니다.
연결 Code는 세션을 종료할 때까지 유효하며, 전송은 AES-GCM으로 암호화됩니다.
Windows 연결 허용 창이 나오면 사용하는 Private Network에서 앱을 허용하세요.
완료된 Stroke·Text·문서 변경을 짧은 간격으로 전달합니다. 필기 도중의 미완성 Stroke는 보내지 않습니다.
서로 다른 요소는 합치며, 같은 요소의 동시 변경은 대체본을 빈 공간에 남기고 검증 요청을 만듭니다.
연결이 끊기면 Local 작업을 보존하고 재연결을 시도합니다. 종료는 공동 편집 메뉴에서 합니다.
인터넷 Relay/외부 Network 공동 편집은 포함하지 않습니다. 한 번 전송하는 데이터는 32MB까지입니다.

정리·문서
Gemini API key는 GEMINI_API_KEY 또는 GOOGLE_API_KEY 환경 변수, 또는 연결 설정에 입력합니다.
자동 AI는 설정에서 켜며 기본 저장 20회·최소 3분 간격, 수동 ‘지금 정리’도 제공합니다.
사용자 문서와 AI 구조화 JSON은 분리합니다. 원본 ID, 기준 Revision, 맥락, 이유, 상태, 관계를 보관합니다.
취소·보류 내용은 검토 문서에 보존합니다. 필기·취소선 인식 품질은 실제 자료 검증이 필요합니다.
문서 → 주제별 문서: 주제마다 별도 편집하고 AI 갱신 제안을 비교합니다.
갱신 비교 → 문단별 선택: 필요한 현재/AI 문단만 골라 편집 결과에 반영합니다.
문서 수정 이력에서 과거 문서와 다른 기기의 대체 문서를 비교·복원할 수 있습니다.
분류 수정에서 대주제·분류·내용·맥락·이유·상태를 직접 수정할 수 있습니다.
배치 정돈은 분류를 이용해 원본 요소를 주제별로 배치합니다. 미리보기 후 적용하며 Undo할 수 있습니다.

검색
찾기 → 모든 Board·Drive 저장본 검색: 구조화 기록, Canvas Text, 사용자 문서, 주제별·검토 문서를 검색합니다.
대주제 → 분류 Filter를 사용하고 결과 선택 시 맥락과 근거를 확인합니다.
AI 관련 검색은 Gemini를 호출해 Keyword가 없는 관련 아이디어도 찾습니다. Keyword 결과와 별도로 표시합니다.
AI가 아직 읽지 않은 손글씨는 직접 Keyword 검색되지 않습니다.
AI 관련 검색은 대상 자료를 Google API로 전송하며 계정의 API 한도·요금이 적용됩니다.

Export / Notion
작업 → Export: 구역 PNG, HTML, Markdown, 원본·맥락 JSON, 문서 PDF, Canvas 구역 PDF.
PDF는 한국어 표시를 보존하는 이미지 기반이며 Text 선택·검색은 HTML/Markdown을 사용하세요.
Notion은 선택 사항입니다. 연결 설정에 Notion Token과 상위 Page ID를 넣고 해당 Page에 Connection을 연결하세요.
문서 → Notion에 보내기로 현재 문서·주제별 문서·검토 기록을 새 Page에 전송합니다.
자동 전송은 하지 않으며, 기존 Notion Page를 덮어쓰지 않습니다.

저장 구조
Local: boards.sqlite(원본·Revision·문서·검증), settings.json(설정·암호화된 Key), Exports.
Drive: ThoughtCanvas/Boards/제목_ID/기기ID/버전/snapshot.zip 및 읽기용 자료.
Drive: ThoughtCanvas/Devices/기기ID.json (기기 이름·최근 등록 시각).
자동 Local 저장은 편집 중단 약 2초 후/계속 작업 시 약 10초, Drive 폴더 저장은 변경된 현재 Board를 약 60초 간격으로 처리합니다.

검증과 남은 사용자 평가
자동 검증 결과는 자동검증결과.txt를 확인하세요.
외부 Gemini·Notion 요청은 테스트 응답으로 검증했으며 실제 계정 전송 검증은 하지 않았습니다.
공동 편집 통신은 Loopback으로 검증했습니다. 실제 두 기기의 Network·Firewall 환경은 사용 시 확인이 필요합니다.
실제 덱빌딩 자료의 AI 품질, 장시간 필기감, Touch 오작동, 대용량 성능은 사용자 평가 항목입니다.
현재 AI 분석 24구역, Export 100구역 제한은 유지됩니다.
모바일은 사용자 요청에 따라 이번 구현 범위에서 제외했습니다.

0.6.1 문서 스타일
AI 본문은 필기를 해설하는 보고서 대신 제목·짧은 목록·핵심어 중심의 Markdown 노트로 생성합니다.
해석 과정과 상세 맥락은 구조화 기록·검증 항목에 보존합니다. 미확인 판단은 간결한 표식을 유지합니다.
읽기 보기, HTML, PDF에서 제목·굵은 글씨·하위 목록·번호 목록을 표시합니다.
편집 화면과 .md 파일은 Markdown 원문입니다. 완전한 Markdown 표·링크·코드 문법 렌더링은 포함되지 않습니다.
기존 문서는 자동으로 다시 쓰지 않습니다. 지금 정리를 실행하고, 직접 수정한 문서는 AI 갱신 제안 비교에서 필요한 부분만 반영하세요.
0.6.2 요청 최적화·문서 구조별 원본
AI 요청은 현재 문서·검증 답변·구조화 맥락을 유지하고, 과거 사용자 편집 전문은 반복 전송하지 않습니다.
과거 편집 이력은 Local/Drive에 그대로 남습니다. 다른 기기의 미통합 대체 문서도 전송 맥락에 보존합니다.
원본 ID는 요청 안에서 짧게 표현하고 응답 저장 시 실제 ID로 복원합니다. 한글 JSON은 직접 UTF8로 전송합니다.
이미지 해상도는 유지합니다. 이전 정리에서 원본 연결이 확보되고 이미지·좌표·원본 ID가 모두 그대로이며 검증 대상이 아닌 구역만 재전송을 생략합니다.
이 최적화는 새 버전에서 첫 정리가 완료된 뒤부터 적용됩니다. 최초 정리와 검증 대상은 전체 이미지를 보냅니다.
작업 → 전체 원본 재분석으로 모든 구역 이미지를 다시 보낼 수 있습니다.
정리 패널에 API가 제공한 입력 Token 수, 이미지 전송/재사용 수, 본문 문자 수를 표시합니다. 문자 수는 Token 수가 아닙니다.
문서 → 문서 구조별 원본에서 주제 → 분류로 탐색합니다. 선택한 원본을 진하게, 주변 맥락을 흐리게 표시합니다.
검색 및 검증의 원본 보기도 같은 구조를 사용하며, 항목이 참조한 과거 Revision을 엽니다.
구역별 보기/index.html과 Canvas-구역.pdf는 문서의 분류 구조를 사용합니다. 전체 격자 HTML/PDF는 별도로 남깁니다.
연결되지 않은 필기는 ‘정리 전·연결 미확인’으로 남깁니다. 없는 과거 원본은 다른 이미지로 대체하지 않습니다.
기존 AI 분류·출처가 잘못된 경우 재정리 또는 분류/검증 수정을 통해 바로잡아야 합니다. 기존 사용자 문서는 자동 변경하지 않습니다.
0.6.3 필기 응답성
Pen 필기가 늦게 표시되던 문제를 개선했습니다. 데이터 형식과 저장·동기화 흐름은 0.6.2와 같습니다.
Pen 입력 묶음마다 변경 알림·화면 갱신을 한 번만 합니다. 네트워크·Drive 폴더 확인은 필기 중에 하지 않고 백그라운드에서 5초 간격으로 갱신합니다.
Offline 중 편집은 이전과 같이 미전송 작업으로 기록됩니다.
S Pen Button 감지 3경로(HID Raw Input 우선, Windows Pen, WPF Stylus)와 판정 규칙은 그대로이며, Button과 무관한 크기 원 중복 갱신과 Report마다의 메모리 할당을 줄였습니다.
Canvas를 Layer로 나눴습니다: 배경·Grid / 완성된 Stroke / Text·선택 표시 / 그리는 중인 Stroke. 필기 중에는 그리는 중인 Stroke만 다시 그리고, 화면 이동 시 Stroke를 다시 그리지 않습니다.
선택 이동(Lasso Drag)은 선택된 Stroke만 다시 만듭니다.
0.6.4 Lasso 이동
선택을 끄는 동안에는 선택된 Stroke의 표시 위치만 옮기고, 실제 좌표와 획 모양은 펜·마우스를 뗄 때 한 번 반영합니다. 선택이 많아도 이동 중 부담이 거의 늘지 않습니다.
Lasso 선택 판정 전에 경계 범위로 먼저 걸러 큰 Board에서 선택 완료가 빨라졌습니다.
실행 폴더에는 WPF 메시지 리소스를 한국어만 포함합니다.
0.6.5 Text 크기·표시 수정
Text Tool을 고르거나 Text를 편집하는 동안 크기 슬라이더가 글자 크기(8~72)를 조절합니다. 편집 중인 Text에는 바로 적용되고, 이후 새로 만드는 Text도 같은 크기로 만들어집니다.
슬라이더를 움직여도 Text 편집이 끝나지 않습니다.
선택 크기 변경은 선택 영역의 중심을 기준으로 확대·축소합니다.
앱을 처음 열 때나 창 크기를 바꾼 직후 일부 Text가 보이지 않던 문제(0.6.3부터)를 수정했습니다.
0.6.6 Text 줄바꿈
Text는 Enter를 누를 때만 줄이 바뀌고, 입력하는 만큼 박스가 옆으로 늘어납니다. 입력 중과 완성 후의 줄바꿈 위치가 같습니다.
이전 버전에서 박스 너비로 자동 줄바꿈되던 Text는 다시 편집할 때 보이던 모양대로 줄을 나눠 엽니다. 편집하지 않은 Text는 그대로입니다.
선택 크기 변경 후에도 Enter로만 줄을 바꾼 Text에는 자동 줄바꿈이 생기지 않습니다.
